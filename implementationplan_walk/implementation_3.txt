MVC Refactoring Plan
The goal is to refactor the current monolithic Express application (server.js) into a clean, scalable Model-View-Controller (MVC) architecture. Currently, all routing logic, AWS S3 operations, external API calls, and in-memory states are squeezed into a single server.js file.

User Review Required
IMPORTANT

Please review this structure before I proceed. This will involve moving code into several new directories and modifying server.js to serve purely as the entry point. Also, please confirm if you want me to refactor the CLI script (index.js) as well, or if we should focus purely on the Express server (server.js).

Proposed Changes
1. New Directory Layout
We will create a src directory to hold the backend code, isolating it from the public view files.

/src
  /config
    - aws.config.js      // AWS S3 client setup
    - env.config.js      // Centralized environment variables parsing
  /models
    - assetModel.js      // Handles the in-memory `assetStatuses` object
  /controllers
    - upload.controller.js   // Handles /api/upload/* logic
    - transcode.controller.js // Handles /api/transcode and /api/callback
    - content.controller.js   // Handles /api/contentslist and /api/contents DELETE
    - status.controller.js    // Handles /api/status/:assetId
  /services
    - api.service.js     // Handles axios requests to Packager and Transcoder
  /routes
    - index.js           // Central router map
    - upload.routes.js
    - transcode.routes.js
    - content.routes.js
    - status.routes.js
  - app.js               // Express app bootstrap and middleware
2. File Restructuring
[MODIFY] server.js
Will become extremely lightweight: it will just import app from src/app.js and call app.listen().

[NEW] src/app.js
Will load Express, CORS middleware, the /public static path, and mount the main router from src/routes/index.js.

[NEW] src/models/assetModel.js
Will extract the global const assetStatuses = {}; into a manageable module that allows getting and setting statuses and packager services.

[NEW] Controllers
We will move the route handler callbacks ((req, res) => { ... }) from server.js to their respective controller files.

[NEW] Routes
We will bridge endpoints to controllers using express.Router().

3. Views
The /public directory already serves effectively as our "Views" layer via static HTML/CSS/JS. They will remain exactly where they are, served by the newly encapsulated app.js.

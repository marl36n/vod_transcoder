S3 Multipart Upload Strategy (Large Files)
To directly answer your question: No, the current application will crash and cannot upload 500GB files.

AWS S3 imposes a hard limit of 5GB per single PUT API request. Additionally, if you try to upload a 500GB file via a single continuous stream and your internet goes out at 499GB, you lose all the progress and have to start over.

To handle 500-600GB files with network interruption resilience, we must completely overhaul the upload mechanism to use AWS S3 Multipart Uploads.

Proposed Changes
To allow massive file uploads and handle network timeouts, the frontend needs to slice the file into small chunks (e.g. 50MB chunks) and upload them independently, retrying chunks that fail.

Backend (server.js)
We will delete the generic /api/presign-upload and replace it with three endpoints strictly designed to coordinate AWS Multipart IDs:

[MODIFY] server.js
POST /api/upload/initiate:
Calls AWS CreateMultipartUploadCommand on the backend.
Returns an UploadId to the UI to uniquely identify this massive transfer.
POST /api/upload/presign-parts:
Accepts the UploadId and the chunk list, dynamically generating a slew of presigned URLs using AWS UploadPartCommand.
POST /api/upload/complete:
Accepts an array of all uploaded ETag IDs.
Calls AWS CompleteMultipartUploadCommand to tell AWS to magically stitch the 10,000 separate chunks back together into one massive 500GB video file.
Frontend (public/script.js)
The Javascript in the user's browser needs to convert into a sophisticated chunk manager.

[MODIFY] public/script.js
Use HTML5 File.slice() API to split the 500GB VOD locally on the browser into 50MB/100MB pieces.
Handle connection interrupts: Set up a loop where if one chunk fails due to a network glitch, it will retry that specific chunk 3-5 times before giving up, meaning you never lose your progress!
Pool the HTTP responses: Extract the ETag header string from every successful S3 chunk upload and store them in memory.
Trigger /api/upload/complete once all chunks are verified to be safe in AWS.
